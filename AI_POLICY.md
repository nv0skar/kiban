# AI Usage Policy

We treat LLMs as analysis, research and implementation aids, not as authors (deductive usage). Use them freely to explore ideas, look up APIs, compare approaches, or check your understanding. You are the only party accountable for code that reaches a release.

## Talking to maintainers

Write your own words. Comments, issue reports, pull request descriptions, and replies in review threads should read as something a person wrote.

An issue should read as your own account of the problem, even when a model helped you find it. A pull request should be something you can describe yourself, both in the description and in follow-up questions — answers copied out of a chat window are not answers.

## Contributions

Work produced by autonomous agents is not accepted. A pull request must have a human author who can speak to any part of the diff without consulting a tool.

Asking a model to suggest an implementation, explain an error, or critique your draft is fine. The final code, comments, and prose must be written by you.

## Quoting model output

If you want to reference something a model produced — an error explanation, a suggested approach — put it in a blockquote and label it as model output. Add your own commentary explaining why it matters and what you concluded. Keep excerpts short, and do not paste whole conversations. Naming the model is optional but helpful.

## AI Usage on Extensions

Code produced by LLMs and autonomous agents is generally allowed in Kiban extensions as long as the code produced is not critical parts (these belong to the mono-repository) and a human-in-the-loop methodology is used. Low-quality vibe-coded extensions are discouraged and never recommended.

## Enforcement

Maintainers may close, hide or reject anything that breaks these rules, and repeated disregard can end in a ban.
